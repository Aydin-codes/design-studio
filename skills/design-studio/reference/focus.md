# Focus: looks, works, or both (step 3)

Ask with job, output and depth: **What matters most here: how it looks, how it works, or both?** It narrows everything after it. Record it in `.studio/state.json` (`focus`) and, if it's their usual answer, as `usual_focus` in the taste profile.

## Works (function first)
For people who want the job done and don't care about color or corners. Respect that; it's their taste.
- **Skip** the taste setup, picking sheets and visual taste questions. Use clean, quiet defaults from the toolkit (a component library's default theme, system fonts, one accent) without asking. State them in one line.
- **References** are products that work well for this job: their flows, density and shortcuts, not their looks.
- **Interview** focuses on tasks: the 3 most common tasks, who does them, how often, on what device, and what goes wrong today.
- **Directions** differ in how the work gets done, not style: fewest steps, most information on one screen, fastest to scan, keyboard-first. Each one says how many steps the main task takes.
- **Build** for speed and clarity: real data, every state (empty, loading, error, long text), fast load, keyboard and screen reader support.
- **Critique** (replaces the visual checks): can someone finish each main task without help? Count the steps. Check errors are clear and recoverable, labels say what things do, the important number or action is found first, and nothing on screen is decoration. Use Nielsen's ten heuristics as the checklist. The tell scan still runs, but only "must fix" items count.

## Looks
The full process as written. Spend the user's time on references, picking sheets and visual directions.

## Both (default if they don't answer)
The full process, and the critique runs the "works" checks as well.
